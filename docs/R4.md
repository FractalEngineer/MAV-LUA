# r4 load fix and pixel previews

Status: **uncommitted candidate, awaiting the user's radio test**. r2 / `v0.1.0` remains the confirmed working checkpoint. r3 failed immediately on FreedomTX 1.4.0 with `attempt to perform arithmetic on a nil value` despite passing the earlier desktop harness.

The cause was reproduced by applying FreedomTX 1.40's C-tail-call fallthrough to the host runner and using an actual C cursor getter. `return lcd.getLastRightPos()` loses its return value on that VM; Navigation then subtracts nil from the screen width. r4 assigns the measurement to a local before returning it. Packaging rejects zero-argument tail calls so this path cannot silently return in a later build.

The GREY capability check also accepts FreedomTX's `lightfunction` native type. Grey remains confined to the instrument ground. Text uses the radio's existing black/white font and integer coordinates.

The old previews stretched antialiased desktop glyphs individually. They have been replaced with the original FreedomTX STD pixel font, with consistent baselines and integer advances. `--font sqt5` selects the alternate font. Neither these font assets nor the desktop renderer ships in the radio script package.

Install `dist/MAV-LUA-tango2-freedomtx-r4.zip`, replacing **both** `SCRIPTS/TELEMETRY/MAV.lua` and `MAV.luac`, then reload the model. Check initial load, Navigation/Message switching, text alignment, solid grey ground and live mode/home telemetry. The [hardware checklist](HARDWARE-TEST.md) covers the remaining checks. Do not commit or push the candidate until the user confirms a working state.
