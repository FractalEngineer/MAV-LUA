# r3 navigation candidate

**Failed on hardware:** the user reported `attempt to perform arithmetic on a nil value` immediately on load. Do not install r3. See [r4](R4.md) for the reproduced firmware tail-call defect and fix. The notes below record what r3 attempted and what its desktop tests missed; r3 was not committed or pushed.

The first hardware-confirmed MVP is preserved at tag `v0.1.0`, commit `9ffc10e`. r3 is a separate candidate; desktop checks do not establish that the additional telemetry and rendering work on FreedomTX 1.4.0 hardware.

Changes:

- Use FreedomTX's proportional text measurements, align navigation values to the right edge, and wrap the complete selected message using actual available width. Typical text needs two preview rows; wide glyphs retain a third.
- Fill the Tango navball's ground solid grey. Keep the horizon, pitch ladder and aircraft reference bright.
- Show the latest message on the bottom navigation line, without page-action hints.
- Show mode at top left and explicit arm state at top right. Decode mode/vehicle type from AP passthrough when `FM` is missing.
- Add home distance to the data list and instrument overlay, with a north-up N/S/E/W dial and a chevron locating the aircraft FROM home. Yaw does not rotate this dial. Use the autopilot/ELRS home report; no local capture-at-arm is required.
- Distinguish `ARMD`, explicit `RDY`/`!RDY`, disarmed with unknown readiness (`RDY?`), and unavailable arm telemetry (`ARM?`). The transport has no pre-arm readiness flag.

The decoder accepts validated F0/F2 AP status, vehicle-type and home tuples. AP status/home expire after three seconds; readiness messages expire after ten seconds. Zero home distance remains unknown because it is also ELRS's uninitialized value. One custom candidate is drained per callback to preserve drawing headroom.

Validation covers malformed/truncated F2 packets with no partial mutation, mode families, cardinal bearings, home distance exponents, readiness/arming transitions, stale state/link recovery, proportional preview wrapping, grey draw flags, all supported display sizes, instruction budgets and retained-heap soaks. Preview images are approximate desktop renderings, not radio screenshots.

Desktop results on 2026-09-12:

- 123 Lua assertions; 25,500 simulated traffic cycles, 0.02 KiB retained-heap growth.
- Worst tested Tango grey/cursor callback: 9,203 script instructions, including full history, full text or nine-tuple packets and extreme attitude. This count excludes Lua mock internals standing in for firmware C APIs. The limit is 10,000.
- 14,299-byte stripped binary; all nested constant tags and string sizes pass independent firmware-ABI validation (seven tests).
- Compiled artifact: 5,000-cycle soak, 33.49 KiB host heap increase with full history, 0.23 KiB subsequent growth. The 64-bit host does not reproduce the radio's allocator or total Lua heap.
- Color widget loading, zone/full-screen callbacks, touch controls and failure handling pass.

Install `dist/MAV-LUA-tango2-freedomtx-r3.zip`, replacing **both** `MAV.lua` and `MAV.luac`, then reload the model. Follow [the radio checklist](HARDWARE-TEST.md), particularly mode/arm state, ground contrast, home direction and prolonged mixed traffic.
